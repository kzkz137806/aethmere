# Aethmere Agent Studio 0.12.0

Windows x64 governed client. It lets a user choose a project, manage the same `.aethmere/context.json` store used by the public Agent Client, select which entries to send to a local Ollama model, and chat without scanning the project.

Studio 0.12.0 requires a connected Aethmere account and a live policy response from `https://app.aethmere.com`. Before every formal context or model capability, the main process obtains an authenticated policy response, flushes any pending terminal events, and waits for the server to acknowledge a start event. If any step fails, the capability does not run. A terminal event that cannot be delivered is stored as an immutable file in `~/.aethmere/governance-spool-studio/`; the next formal capability is blocked until it is delivered.

The renderer has no network capability. Automatic requests from the main process are limited to `https://app.aethmere.com` for account/governance traffic and loopback Ollama at `http://127.0.0.1:11434` for the model. Official website and GitHub links open only after a user clicks them.

Governance events use a closed schema and contain only client/version/platform, policy digest, step, result, structured reason, coarse duration/attempt/day buckets, and random flow/event IDs. They do **not** contain prompts, answers, project content, context text, paths, URLs, IP addresses, user-agent strings, account tokens, or secrets. Project content is sent only to the user's loopback Ollama instance.

Versions before 0.12.0 were legacy offline previews. They do not have this governance chain and cannot be remotely upgraded into governed clients; stop distributing them and ask users to install 0.12.0 or later.

Sign in with a one-time computer connection code generated by the Aethmere app. Studio reads and writes the shared account record at `~/.aethmere/account.json`, so a current Agent Client authorization can also be reused. The authenticated policy must contain complete `agent_client`, `studio`, and `vscode` entries in both its minimum and latest version maps, plus the fixed update address `https://aethmere.com/downloads/`; missing or malformed version policy fails closed. The service may raise the minimum supported Studio version and announce a newer version; below-minimum clients fail closed.

## Development checks

```bash
npm --prefix studio test
```

## Windows package

Set `AETHMERE_ELECTRON_DIST` to a reviewed Windows x64 Electron distribution and run:

```powershell
$env:AETHMERE_ELECTRON_DIST = "C:\path\to\electron\dist"
npm --prefix studio run package:win
```

The build compiles a small public launcher and keeps Electron inside `runtime/`, so ambient Electron logging cannot mutate the extracted package directory. The required release asset name is `aethmere-studio-0.12.0-windows-x64.zip`, with `aethmere-studio-0.12.0-windows-x64.zip.sha256.txt` beside it. The output is an unsigned portable client, not an installer. Distribute the complete ZIP with its SHA-256 checksum; never distribute the `.exe` alone. Code signing and the repository's existing license/product-scope mismatch remain release blockers; this implementation does not alter legal terms.
